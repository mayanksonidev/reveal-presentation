📦 Docker Volume

The volume is Docker saying: "Relax, I'll keep this somewhere safe — outside the container."

docker-compose.yml

The stack at a glance


services:
  postgres:
    image: postgres:16
    environment:
      POSTGRES_DB:       keycloak
      POSTGRES_USER:     keycloak
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
    volumes:
      - postgres_data:/var/lib/postgresql/data

  keycloak:
    image: quay.io/keycloak/keycloak:25.0
    command: start-dev
    environment:
      KC_DB:          postgres
      KC_DB_URL:      jdbc:postgresql://postgres/keycloak
      KC_DB_USERNAME: keycloak
      KC_DB_PASSWORD: ${POSTGRES_PASSWORD}
    ports:
      - "8080:8080"
    depends_on:
      - postgres

volumes:
  postgres_data:

Three things making this work

1 · Separation

🐘 Postgres in its own container

Keycloak and Postgres are decoupled — each can restart independently.

2 · Persistence

📦 Named Volume

postgres_data lives on the Docker host, not inside the container.

3 · Secrets

🔑 .env file

Passwords stay out of your compose file and out of version control.

Four things that will bite you

I've hit all of these so you don't have to.

1

🔌 Keycloak can't connect to the database

·

The host in KC_DB_URL is localhost. Should be the service name.

KC_DB_URL: jdbc:postgresql://postgres/keycloak
2

🔑 Changed the password, now nothing works

·

Postgres only sets credentials when the volume is empty. Old password sticks.

docker compose down -v && docker compose up -d
3

🚪 Port 8080 is already taken

·

Change the left side of the mapping, not the right.

ports:
  - "8081:8080"
4

🔄 Keycloak keeps restarting

·

Give the Postgres healthcheck more retries or a longer interval.

healthcheck:
  retries: 10
  interval: 5s

Is this production-ready?

Honest answer: not yet. start-dev is called dev mode for a reason.

⚙️
start instead of start-dev — plus a real hostname (KC_HOSTNAME), TLS, or a reverse proxy in front
🔒
Passwords out of the Compose file — into an .env file or proper secrets manager
📌
Pinned image versions — and Postgres not exposed to the outside world
💾
Backups of that volume — pg_dump is your friend
❤️
Health endpoints on — KC_HEALTH_ENABLED=true, served on port 9000 · perfect for Kubernetes liveness and readiness probes

Quick recap

  • ✗ Default Keycloak stores data inside the container — it dies with it
  • ✓ The fix: PostgreSQL + a named volume
  • ✓ A healthcheck and depends_on make Keycloak wait for the database
  • ✓ Use the service name, not localhost
  • ! down keeps your data · down -v deletes it
