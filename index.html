MySQL Deployment + PersistentVolumeClaim

MySQL Deployment Without PVC

Default container execution uses the temporary container filesystem layer. 

# mysql-deployment-no-pvc.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: mysql
spec:
  replicas: 1
  selector:
    matchLabels:
      app: mysql
  template:
    metadata:
      labels:
        app: mysql
    spec:
      containers:
        - name: mysql
          image: mysql:8.0
          ports:
            - containerPort: 3306
          # No volumeMounts or volumes configured

State Lifecycle Limitations:

  • Data written to /var/lib/mysql resides in the writable container layer.
  • Pod restart or deletion replaces the container instance.
  • All database records are destroyed upon pod termination.
Pod Termination Verification
$ kubectl delete pod mysql-6879989f5d-xk9z2
pod "mysql-6879989f5d-xk9z2" deleted
$ curl http://localhost:3000/users
[]  # Data lost on pod recreation

Step 1: Define PersistentVolumeClaim

Request storage resource allocation independently of the pod lifecycle. 

# mysql-pvc.yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: mysql-pvc
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 1Gi

accessModes: ReadWriteOnce (RWO)

Volume mounted as read-write by a single node.

resources.requests.storage: 1Gi

Requests 1 Gigabyte of storage capacity.

kubectl apply & get pvc
$ kubectl apply -f mysql-pvc.yaml
persistentvolumeclaim/mysql-pvc created
$ kubectl get pvc
NAME       STATUS  VOLUME         CAPACITY
mysql-pvc  Bound  pvc-a1b2c3d4   1Gi

Step 2: Update MySQL Deployment with PVC

Configure volumeMounts and volumes to attach the PersistentVolumeClaim. 

# mysql-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: mysql
spec:
  replicas: 1
  template:
    spec:
      containers:
        - name: mysql
          image: mysql:8.0
          ports:
            - containerPort: 3306
          volumeMounts:
            - name: mysql-storage
              mountPath: /var/lib/mysql
      volumes:
        - name: mysql-storage
          persistentVolumeClaim:
            claimName: mysql-pvc

volumeMounts

Mounts volume mysql-storage at container directory /var/lib/mysql.

volumes.persistentVolumeClaim

Binds container storage to claimName: mysql-pvc.

+ volumeMounts:
    - name: mysql-storage
      mountPath: /var/lib/mysql
+ volumes:
    - name: mysql-storage
      persistentVolumeClaim:
        claimName: mysql-pvc

Manifest Specification Comparison

Configuration Without PVC With PVC
Storage Location Container local layer (`/var/lib/mysql`) Persistent Volume mounted at `/var/lib/mysql`
Pod Spec Configuration No `volumes` or `volumeMounts` defined `volumeMounts` defined in container spec
`volumes.persistentVolumeClaim` defined in pod spec
Lifecycle Dependency Tied directly to container instance Decoupled from pod lifecycle
Pod Recreation Effect Data lost permanently Data retained and remounted
